# Generators

Each asset kind is generated by one provider, chosen with `NAUCTO_<KIND>_PROVIDER`. A kind whose
provider is unset (or missing credentials) is disabled, and the assistant falls back on Naucto's
native tools: `design_sfx`, `convert_midi`, catalogued art.

| Provider | Kinds | Cost |
|---|---|---|
| `space` — Naucto's ZeroGPU Space (default) | sprite, midi, sample | Hosting free. GPU time is charged to the ZeroGPU quota of the account owning `HF_TOKEN`: 5 min/day free, 40 min/day with PRO ($9/month), then $1 per 10 GPU-minutes of credits |
| `pixellab` — [PixelLab](https://www.pixellab.ai) pixel-art API | sprite | Their subscription (from about $12/month for ~2,000 images) |
| `endpoint` — any HTTPS service speaking the contract below | any | Whatever it costs (e.g. a Hugging Face Inference Endpoint, $0.50+/hour) |

Only the prompt and the asset's constraints leave the service. Responses are capped at 2 MiB,
validated and converted into Naucto's formats; provider error text is never stored.

## The Space (`providers/space`)

One Gradio app with a route per kind, each decorated with `@spaces.GPU`:

| Kind | Model | Licence | Rough GPU time per call |
|---|---|---|---|
| `midi` | [amaai-lab/text2midi](https://huggingface.co/amaai-lab/text2midi), upstream code pinned by commit and hash | Apache-2.0 | 30–90 s |
| `sprite` | [SDXL base](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0) + [pixel-art-xl](https://huggingface.co/nerijs/pixel-art-xl) LoRA, then palette quantization | OpenRAIL++ / CreativeML OpenRAIL-M | 5–15 s |
| `sample` | [Stable Audio Open 1.0](https://huggingface.co/stabilityai/stable-audio-open-1.0) (gated) | Stability AI Community License: free below USD 1M annual revenue | 10–20 s |

Times are estimates until measured with `npm run evaluate`. With the free 5 minutes a day that is
roughly 3–10 songs or 20–60 sprites; PRO's 40 minutes, 8× that.

### Deploying it

1. On Hugging Face, create a **Space** under the Naucto organization (or your account): SDK
   **Gradio**, hardware **ZeroGPU**. A free account older than 30 days can host 2 ZeroGPU Spaces;
   an organization needs the Team plan. Prefer **private**. A public Space is also safe to leave
   open: every caller spends their own quota, never yours, but anyone could use it.
2. `scripts/build-space.sh`, then push `build/space/` to the Space repository (commands in the
   script's header). The build fetches the upstream text2midi code at a pinned commit and refuses it
   if its hash differs.
3. In the Space's **Settings → Variables**, enable what you want:
   `MIDI_MODEL=amaai-lab/text2midi`, `MIDI_REVISION=<commit of the model repo>`,
   `SPRITE_MODEL=stabilityai/stable-diffusion-xl-base-1.0`, `SPRITE_LORA=nerijs/pixel-art-xl`,
   and for samples `SAMPLE_MODEL=stabilityai/stable-audio-open-1.0` plus a **secret** `HF_TOKEN`
   from an account that accepted that model's licence.
4. Wait for the build, try a tab in the Space page, then configure the service:

   ```sh
   NAUCTO_SPACE_URL=https://<org>-<space-name>.hf.space   # shown under "Embed this Space"
   HF_TOKEN=hf_…            # read access to the private Space; its account's quota pays the GPU
   NAUCTO_MIDI_PROVIDER=space
   NAUCTO_SPRITE_PROVIDER=space        # or pixellab
   NAUCTO_SAMPLE_PROVIDER=space        # only if SAMPLE_MODEL is set on the Space
   ```

5. `npm run evaluate -- midi 3` to check output survives conversion.

The Space keeps running a generation after the service cancels it (the quota is still used), and a
sleeping Space takes a minute to wake: the first call after a pause can time out; call again.

## PixelLab

`NAUCTO_SPRITE_PROVIDER=pixellab` and `PIXELLAB_TOKEN`. The service calls `create-image-pixflux`
with a transparent background at `PIXELLAB_MIN_SIZE` (32) or larger, then downsamples and
quantizes onto the game palette exactly as the Space does. It accepts the image inline (base64) or
as a link on PixelLab's own domain; anything else is refused. The adapter follows PixelLab's
published documentation and is tested against a stand-in, not their live API: check the first
real call.

## Endpoint contract

Every request is `POST` with `Authorization: Bearer $HF_TOKEN` and the body
`{"inputs": "<prompt>", "parameters": {…}}`. Redirects are refused.

| Kind | `parameters` | Response |
|---|---|---|
| `sprite` | `width`, `height` (8–64), `palette` (16 `#rrggbb`) | `{"width","height","pixels":[0–15, row-major]}` — index 0 is transparent |
| `midi` | `max_beats` | `{"midiBase64": "<Standard MIDI File>"}` |
| `sample` | `seconds` (≤ 1), `sample_rate: 8000` | `{"pcm8Base64": "<signed 8-bit mono>", "sampleRate": 8000}` — ≤ 8192 bytes |

The Space answers the same objects, plus the `model` that produced them, on
`/gradio_api/call/<kind>` with `data = [prompt, JSON.stringify(parameters)]`. Set
`HF_<KIND>_ENDPOINT` and `HF_<KIND>_MODEL` (the identifier recorded as provenance) for `endpoint`.

## Development

- `npm run test:providers` — the Python conversions and request validation, no GPU needed.
- `npm run stub` — stand-ins for the Space, an endpoint and PixelLab on port 3199. Tests only.

## Operation

- Defaults: 2 concurrent requests per service, `AI_JOBS_PER_PROJECT_HOUR` (20) per project,
  five-minute timeout, no automatic retries.
- Cancelling a queued job prevents dispatch; cancelling a running one aborts the request and the
  Backend discards any late result, but the provider may already have done (and counted) the work.
- A job lost with the service is failed by the Backend after ten minutes, never resubmitted.
